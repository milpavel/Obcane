# Personalized portal newsletter

Public page `/novinky/` and homepage teaser. Six topics: original/editorial news, city/school/community news, culture/events, sport, restrictions, classifieds. Daily at 18:00 Prague time or Friday at 18:00. The schedule handles DST in Postgres; mail delivery is queued and can follow the scheduled start.

Double opt-in: public requests do not activate delivery or change an existing active subscription. Confirmation token expires in 24 hours and is single-use. Existing subscribers can request a private access email. Management and unsubscribe require scoped HMAC links; one-click mail-provider unsubscribe uses a separate scoped key and POST, never a state-changing GET. Cancellation revokes management links. No existing suggestions, advertisers or contacts are subscribed automatically. Emails are private, RLS enabled, no public Data API grants. No new Auth settings or credentials.

News selection uses published own posts, public imported items after editorial overrides, manual events, and approved non-expired classifieds. Initial inventory is seeded before launch. Existing item first-seen timestamps remain stable across imports and text changes. Ordinary news must appear and be published after confirmation; no import-time promotion of old dated news. Events may predate signup but must be in the coming seven days, with known start still ahead for events today. Expired restrictions and inactive/draft items are removed. At most ten entries per digest, topical variety, no duplicate item/canonical URL. Reserved delivery keys prevent repeats across daily/weekly messages. No email when selection is empty.

The new `obcane-newsletter` function has a dedicated minute cron `obcane-newsletter`. It refreshes sources every fifteen minutes, queues due summaries and sends up to three messages per invocation. It reuses the existing verified project-scoped Seznam SMTP mailbox and master mail pause. Confirmation mail takes priority, retries are bounded, SMTP acceptance is recorded. Initial internal capacity guard is 200 newsletter emails per rolling 24 hours, shown with queue counts in admin; scale the transport/capacity before substantially exceeding that audience. Stable Message-ID reduces duplicate processing on retries. SMTP acceptance is not an inbox or read receipt.

Admin E-maily redakce contains subscriber counts, pending confirmations, sent summaries, failed mail, source freshness and queue/capacity information; editors can retry failures. No tracking pixels.

Validation: complete repository checks; preference/token/email/HTML boundary tests; filtering and deduplication; Prague scheduling; real API signup/inspect/confirm/change/unsubscribe with a disposable example.com address, private-token rejection and one-use confirmation. The QA subscription was removed before dispatch, so no example.com mail was sent. Initial source sync and cron confirmed successful; RLS/grants verified. Browser UI tested with a local simulated API, plus mobile overflow checks. Newsletter SMTP uses the mailbox transport already verified in administration.
